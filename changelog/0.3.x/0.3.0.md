# 0.3.0 — 2026-11-04

## Added

- **`skill://faa-traffic-delays-guide/SKILL.md`** is the server's first published agent skill (`skills/faa-traffic-delays-guide`). `createApp({ skills: 'skills' })` lists it in `resources/list`; plugin hosts load it from the repository, and the `.mcpb` bundle and Docker image ship it.
- **`plannedPrograms`** on each `faa_delays_get_airport_status` row lists the operations plan's terminal items naming the airport, with the plan's `advisory`. `[]` when the plan names it nowhere; absent, with a `notice`, when the plan could not be read. `status` is unchanged. ([#28](https://github.com/cyanheads/faa-traffic-delays-mcp-server/issues/28))
- **`airports`** on `faa_delays_get_operations_plan` terminal items gives the FAA identifiers the item names (`SEA/BFI` → `SEA`, `BFI`); absent for a metro area or an ARTCC. ([#28](https://github.com/cyanheads/faa-traffic-delays-mcp-server/issues/28))
- **`closure`** on `faa_delays_get_airport_status` gains `notamText`, `notamNumber`, and `issuedAt`, the fields `closureNotam` carries. ([#25](https://github.com/cyanheads/faa-traffic-delays-mcp-server/issues/25))
- **`dailyWindowUtc` and `inEffect`** on `closure` and `closureNotam`, and on the matching `faa_delays_list_active_events` rows, for a NOTAM scheduled `DLY HHMM-HHMM`. A `notice` names the next window. ([#26](https://github.com/cyanheads/faa-traffic-delays-mcp-server/issues/26))
- **`effectiveStart` and `effectiveEnd`** on `faa_delays_get_advisory` give `effectiveTime` as ISO 8601 UTC. The end resolves only into the start's month or the next; a later end omits both fields (`311800-311700` on 2026-03-31). ([#29](https://github.com/cyanheads/faa-traffic-delays-mcp-server/issues/29))

## Changed

- **`closureText`** on `airport_closure` rows of `faa_delays_list_active_events` is the NOTAM text instead of the closure's exception wording, which it falls back to when the FAA sends no NOTAM text; `closure_notam` rows fall back the same way. ([#25](https://github.com/cyanheads/faa-traffic-delays-mcp-server/issues/25))
- **Daily closures** outside their window no longer set `status: "closed"` on `faa_delays_get_airport_status`, which moves on to the next precedence level; its text heading reads `Airport closure` rather than `Airport closed`. In `faa_delays_list_active_events` such a row sorts with closure NOTAMs. ([#26](https://github.com/cyanheads/faa-traffic-delays-mcp-server/issues/26))
- **`sentAt`** on `faa_delays_get_advisory` is ISO 8601 UTC, as in `faa_delays_list_advisories`, instead of the printed `YY/MM/DD HH:MM`; omitted when the signature names no real minute. ([#29](https://github.com/cyanheads/faa-traffic-delays-mcp-server/issues/29))
- **`limit`** on `faa_delays_list_advisories` has no maximum (it was 200); a UTC date lists at most 999 advisories, so 999 returns any date whole. ([#27](https://github.com/cyanheads/faa-traffic-delays-mcp-server/issues/27))
- **Airport status notices** no longer point to `faa_delays_get_operations_plan` when every airport is quiet and the plan was read.
- **Packaging and tooling** sync the mcp-ts-core 0.13.18 template: root `plugin.json` and `mcp.json`, anchored `.mcpbignore`, `skills/` in the Docker image and npm `files`, Bun 1.4.3 → 1.4.4 images, and `minimumReleaseAge` 3 days → 1 day.

## Fixed

- **Multi-line `closureNotam` `text`** keeps its line breaks in the `content[]` of `faa_delays_get_airport_status` instead of running together on its `Restriction:` line.
